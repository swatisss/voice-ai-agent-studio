# Purpose

Every voice-agent platform surveyed reports lifecycle through signed webhooks and mirrors them with GET ([ADR-0012](/decisions/adr-0012-public-api-and-supervisor-routing.md)). A tenant backend learns that a conversation it started through the [public API](/api/public-api.md) was transferred, escalated, ended or scored without polling.

# Endpoints

Table `webhook_endpoints` ([/data/data-model.md](/data/data-model.md)); at most 5 per tenant; managed in Settings → Webhooks ([/ui/settings.md](/ui/settings.md)) through `/api/webhooks` ([/api/rest-api.md](/api/rest-api.md)).

| Field | Rules |
|---|---|
| `url` | `https://` only (`http://localhost` allowed when not on Cloud Run); ≤ 500 chars |
| `events` | non-empty subset of the event types below |
| `include_transcript` | default `false` |
| `enabled` | default `true` |
| `secret` | generated by the platform (`whsec_` + 32 base62 chars), shown once on create and on **Rotate**; stored encrypted with `TENANT_SECRETS_KEY` like tenant credentials ([/architecture/tenant-settings.md](/architecture/tenant-settings.md)), because signing needs it |

# Events

Only conversations with `source: api` produce webhooks.

| Type | When | `data` |
|---|---|---|
| `conversation.started` | the conversation is created | `{conversation_id, external_id, metadata, channel, transport}` |
| `conversation.transferred` | a transfer chose the next agent ([/architecture/agent-transfer.md](/architecture/agent-transfer.md)) | `+ {from_agent_id, to_agent_id, segment}` |
| `conversation.escalated` | a segment escalated to a human | `+ {escalation_id, reason_category}` |
| `conversation.ended` | the conversation ended | `+ {status, outcome, end_reason, segments: [{call_id, agent_id, outcome}]}` |
| `conversation.analyzed` | every segment of an ended conversation has a scorecard | `+ {outcome, segments: [{call_id, agent_id, outcome, score, hard_fail}]}`; with `include_transcript`, also `transcript` (as the API view) |

Every event repeats `conversation_id`, `external_id` and `metadata`. No event carries member identifiers, the caller's number or the transcript unless the endpoint asked for the transcript; the tenant otherwise fetches details with `GET /conversations/{id}`.

# Delivery

* Body: `{"id": "evt_…", "type": "…", "created_at": "…", "tenant_id": "…", "data": {…}}`. `id` is stable across retries and resends, so receivers deduplicate on it. Order is not guaranteed.
* Signature header `X-VoiceAI-Signature: t=<unix seconds>,v1=<hex HMAC-SHA256 of "<t>.<raw body>" keyed with the endpoint secret>`. Receivers SHOULD reject a `t` older than 5 minutes. During the 24 h after a rotation the header carries a second `v1` signed with the previous secret.
* One `webhook_deliveries` row per event and endpoint; the job `deliver_webhook` posts it with a 10 s timeout. A 2xx response is delivered. Anything else is retried after 10 s, 1 min, 5 min, 30 min, 2 h and 6 h (7 attempts), then `failed`. Redirects are not followed.
* `POST /api/webhooks/deliveries/{id}/resend` queues a fresh attempt of a delivered or failed row with the same event id.
* Deliveries older than 30 days are deleted by the daily purge.

# Acceptance

- **WH-01** — Given an endpoint subscribed to `conversation.ended`, when an API text conversation ends, then one POST arrives with type `conversation.ended`, the conversation's `external_id` and `metadata`, and a `X-VoiceAI-Signature` whose `v1` equals HMAC-SHA256(secret, "t.body"); no request is made for a Studio or phone conversation.
- **WH-02** — Given an endpoint that answers 500 twice and then 200, then the delivery is `delivered` after three attempts spaced per the schedule, every attempt carries the same event `id`, and a delivery whose endpoint never answers 2xx is `failed` after 7 attempts.
- **WH-03** — Given `include_transcript: false`, then no payload contains transcript text, a member reference or a phone number; given `true`, `conversation.analyzed` includes the transcript.
- **WH-04** — Given a webhook endpoint, then its secret is returned only by create and rotate, is not stored in plain text, and after a rotation deliveries for 24 h carry signatures with both secrets.
- **WH-05** — Given a failed delivery, when it is resent, then a new attempt is made with the same event id and the row shows the new status.
