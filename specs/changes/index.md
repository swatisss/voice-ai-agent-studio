# Change proposals

* [CP-0001 Initial platform build](cp-0001-initial-platform.md) - Build the v1 platform: builder, voice and text test calls, escalation with groundwork packets, fleet learning with eval-gated fixes
* [CP-0002 Spec enforcement in CI and contributor onboarding](cp-0002-spec-enforcement-and-onboarding.md) - CI gate, PR-level spec-first/log/lifecycle rules, acceptance ratchet, setup script, README
* [CP-0033 Ship what was proven, and a steadier gate](cp-0033-proven-fixes-and-a-steadier-gate.md) - Approval publishes the published version plus the fix; cluster cases repeat, lift is a pass rate, small clusters keep a held-out case, latency blocks only past the agent's budget
* [CP-0032 Learning actions](cp-0032-learning-actions.md) - Learning runs turn findings into ranked actions (fix did not hold, answer needed, check failing, drift, scenario failing) that close themselves; knowledge is drafted only from human answers
* [CP-0031 Website knowledge sources](cp-0031-website-knowledge-sources.md) - One URL indexes a page or a whole site section (sitemap or links, robots.txt), keeps headings, cites pages, re-syncs daily or weekly so agents answer from the live site, and refuses internal addresses
* [CP-0030 Full knowledge chunks, sound "never" checks, verification only where it exists](cp-0030-knowledge-judge-verification-fixes.md) - Search returns whole chunks; text replies are the recorded text; never-checks lose the double negative and a hard-gate fail must quote the breach; agents without a verification tool stop asking for member ID and date of birth; builder warning
* [CP-0029 Configurable decision-model time budgets](cp-0029-configurable-decision-model-timeouts.md) - The voice and text time budgets of the decision model become environment settings, so a hosted decision model can decide voice conversations while the connecting message plays; the embedding stays the fallback
* [CP-0028 Routing mode - embedding or a configured decision model](cp-0028-routing-strategies-and-local-laya.md) - The embedding routes by default; a generic Jev-compatible decision model is switched on by configuration and falls back to the embedding; Jev/Laya/LLM targets and local Laya removed; the routing suite compares both modes
* [CP-0027 WebRTC transport](cp-0027-webrtc-transport.md) - WebRTC as a third voice transport: SDP offer/answer with a single-use token, control data channel, TURN on Cloud Run
* [CP-0026 Agent-to-agent transfer](cp-0026-agent-transfer.md) - transfer_to_agent hands a conversation to the agent the supervisor picks; verification and context carry over, same voice, at most 3 transfers; misroute checks and nightly routing proposals
* [CP-0025 Supervisor routing and the front desk](cp-0025-supervisor-routing.md) - Front desk plus two-stage routing (embeddings, then Jev, Laya or LLM with failover and PHI mode), clarifying questions, default agents, front-desk numbers, full-flow playground with routing trace
* [CP-0024 Capability catalog and routing suite](cp-0024-capability-catalog.md) - Editable use cases, description and routable flag in the snapshot, auto re-indexed capability profiles, a tenant routing suite
* [CP-0023 Public API, API keys and webhooks](cp-0023-public-api-and-api-keys.md) - /v1 per tenant with hashed scoped keys, text (JSON/SSE) and voice (WebSocket, media stream) with connect tokens, rate limits, signed webhooks
* [CP-0022 Nightly self-learning](cp-0022-nightly-self-learning.md) - A nightly run drafts knowledge, tool, skill and rule proposals from each agent's signals, gates them offline (held-out, test suite on both arms, no slowdown) and queues them in a learning inbox; only a human publishes
* [CP-0021 Test suites](cp-0021-test-suites.md) - Editable test scenarios per agent with personas, expected tools and results and stand-in memory; runs of k repeats against the published version, the draft or an earlier version, scored and reported as pass^k; Run tests in the builder (report only)
* [CP-0020 Call scoring and online evaluation](cp-0020-call-scoring-and-online-evaluation.md) - Every real call gets a scorecard of checks derived from its agent version (code first, judge second, hard gates for safety); per-version rollups, drift, human reviews and judge calibration; a new Evaluation page
* [CP-0019 Agent memory and caller verification](cp-0019-agent-memory-and-caller-verification.md) - Agents remember verified members across calls and maintain that memory themselves; registered phone numbers identify callers, the date of birth verifies them
* [CP-0018 The text loop drives the turn policy](cp-0018-text-loop-drives-turn-policy.md) - respond() drives the same turn-policy events as the realtime bridge; text calls store the same event data as realtime calls
* [CP-0017 Effective call settings](cp-0017-effective-call-settings.md) - One resolution of persona, turn detection and pipeline for a call; live changes go through the session and the pipeline subscribes
* [CP-0016 Turn policy inside AgentSession](cp-0016-turn-policy-in-agent-session.md) - Events in, decisions out: the cascade loop and the realtime bridge stop re-implementing turn rules and their order
* [CP-0015 Call admission](cp-0015-call-admission.md) - One decision for every way a voice call starts; voice calls with no usable key are refused up front
* [CP-0014 Tenant pipeline allowlist and per-tenant OpenAI key](cp-0014-tenant-pipeline-allowlist-and-openai-key.md) - Realtime is opt-in per tenant (save, publish, call start); a tenant's own encrypted OpenAI key serves its realtime calls, with optional platform fallback; Settings page
* [CP-0013 One-command phone demo](cp-0013-one-command-phone-demo.md) - scripts/phone_demo.py: fill in .env, run one script, call the number
* [CP-0012 Phone channel (Twilio) and optional realtime speech-to-speech voice](cp-0012-phone-channel-and-realtime-voice.md) - Inbound Twilio calls to published agents, OpenAI Realtime as a per-agent pipeline, new Insurance Claims Agent, local phone runbook
* [CP-0011 Calls close properly and callers rate them](cp-0011-call-ending-and-feedback.md) - Hand-off, farewell, silence and max length end calls; thumbs up/down after a call feeds Insights
* [CP-0010 Simpler Test call page and a spoken welcome in voice calls](cp-0010-simpler-test-call-and-voice-welcome.md) - No use-case cards, Talk | Type in the call card, technical details behind a switch, the agent speaks first in Talk mode
* [CP-0009 Simplified UI - left navigation, focused dashboard, Echo Mind branding](cp-0009-simplified-ui-sidebar-and-branding.md) - Left sidebar replaces the top header, four-tile dashboard (calls, containment, escalated to human, response time), product named Echo Mind Voice Agent Studio
* [CP-0008 OpenAI as a third LLM provider](cp-0008-openai-provider.md) - OpenAI key from .env, two OpenAI models, last fallback of every role, one-line role switch, health dot
* [CP-0006 Customer Support & Channels use cases](cp-0006-customer-support-use-cases.md) - Seven insurer use cases, outbound and internal call modes, synthetic insurance API and knowledge, use-case gallery
* [CP-0007 Turn-detection modes and a persona library](cp-0007-turn-detection-and-personas.md) - Normal/semantic turn detection and personas, configurable per agent, per call and live from the UI
* [CP-0005 Health-insurer portal look and feel](cp-0005-insurer-portal-theme.md) - Blue brand palette, top navigation, pill buttons, WCAG AA contrast (checked by a test)
* [CP-0004 One-command dev launcher](cp-0004-one-command-dev-launcher.md) - scripts/dev.py starts web + API together with prefixed logs and clean shutdown
* [CP-0003 Honor LLM role overrides from apps/api/.env](cp-0003-env-file-role-overrides.md) - LLM_ROLE_<ROLE> now works from the .env file, not only real environment variables
