* **Creation**: [CP-0012](changes/cp-0012-modular-boundaries-and-llm-wire-port.md) (accepted and implemented the same day), [modular structure](architecture/modular-structure.md) and [ADR-0008](decisions/adr-0008-modular-monolith.md); new acceptance prefix `MOD` (MOD-01…MOD-08), plus LG-12…LG-15 and MT-05.
* **Update**: [LLM gateway](architecture/llm-gateway.md) (`wire:` and `options:` on provider entries, an "Adding a provider" section, the Groq usage quirk restated as `options.usage_extra_key`, the fake responder described as role-level), [ADR-0003](decisions/adr-0003-llm-gateway.md) (amendment: the single OpenAI-compatible client is now one adapter behind a port), [multi-tenancy](architecture/multi-tenancy.md) (one shared owned-row helper; child rows filter on their own `tenant_id` instead of trusting the parent), [jobs and events](architecture/jobs-and-events.md) (handlers registered explicitly from a declared list; the bus is best-effort and must not trigger durable work), [tools and skills](architecture/tools-and-skills.md) (execution through the `ToolCaller` port; transport is adapter configuration, and a future MCP transport is another adapter), [knowledge](architecture/knowledge.md) (the two embedders are adapters behind the `Embedder` port), [system overview](architecture/system-overview.md) (components map onto the eight modules), [deployment](architecture/deployment.md) and [GCP runbook](build/runbook-gcp.md) (`/healthz` provider keys come from `models.yaml`), [conventions](process/conventions.md) (`MOD` prefix; the `Spec:` docstring rule is enforced).
* **Clarification** while writing the specs: post-call analysis is a **port** owned by `ports/`, not a function on `learning`'s contract, because `learning` already names `conversation` to drive simulated calls and the module graph must stay acyclic — the asymmetry is the design. Escalation *triggers* cannot leave the turn loop, so `handoff` is drawn at the human console rather than at the safety screen. `analytics` owns no tables and exists so the dashboard has somewhere to read across modules from, which is the coupling it had.
* **Disproved while reviewing**: the readiness gate was *not* re-derived in the insights route as first thought; the real defect there is that three handlers build a 28-day, tenant-wide cluster aggregate to read one boolean. Also found, and not in the original review: `voiceai chat` drains the job queue without ever importing the handler modules, so its post-call analysis has silently never run.
* Implemented: `scripts/arch_check.py` (seven static rules, run in CI; 17 tests on synthetic package trees), `ports/llm.py` and `adapters/llm/{registry,openai_compatible}.py` (the gateway keeps `stream_chat`/`chat`/`complete_json` and all its helpers, so no call site moved), `config.py` (`extra="allow"` plus `env_value()`, which also fixed an `and`/`or` precedence bug in `provider_configured`), `routes/meta.py` (`/healthz` derived from `models.yaml`), `config/models.yaml` (`wire:`, `options:`), `jobs.py` + `main.py` + `cli.py` (declared handler kinds, explicit registration, start-up error when one is missing), `db.py` (`get_owned`). 31 new tests (`tests/test_arch_check.py`, `tests/test_llm_wire_port.py`, `tests/test_tenant_scoping.py`); `tests/test_llm_gateway.py` retargeted to the wire adapter and its `real_mode` fixture isolated from the developer's own `apps/api/.env`, which had been making two role-fallback tests fail locally while passing in CI. All touched specs are `status: stable`.
